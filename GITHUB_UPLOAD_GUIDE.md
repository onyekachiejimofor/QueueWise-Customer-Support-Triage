# Publish QueueWise to GitHub — no programming required

1. Extract `QueueWise-FINAL-GitHub-Portfolio.zip`.
2. Open the **inner folder** `QueueWise-Customer-Support-Triage` and make sure it contains `README.md`, `assets`, `data`, `docs`, `reports`, and `scripts`.
3. On GitHub, create a **public** repository named `QueueWise-Customer-Support-Triage`. Do not select “Add a README” because one is already included.
4. In the new empty repository select **uploading an existing file** and drag the contents **inside** the inner project folder, preserving folder paths. Alternatively use GitHub Desktop and add the local folder as a repository.
5. Commit using: `Publish QueueWise human-in-the-loop ticket triage case study`.
6. Check that README images render and the links to `docs/03_casebook.md`, `data/processed/final_labeled_tickets.csv`, and `reports/revision_history.csv` work.
7. Pin the repository on your GitHub profile and describe it using the topics suggested below.

**Repository description:** `Human-in-the-loop classification of 240 synthetic support tickets into 8 queues, with Label Studio evidence, ambiguous-case reasoning, reference-guided QA, and auditable revisions.`

**Suggested topics:** `data-annotation`, `label-studio`, `text-classification`, `data-quality`, `nlp-annotation`, `customer-support`, `human-in-the-loop`, `portfolio-project`.

**Important:** This package does not publish itself and is not already uploaded to your GitHub account. Do not edit the metrics to say “independently validated 100% accuracy”; the reference was consulted during revision.
